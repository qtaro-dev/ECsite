# T48 商品画像のアップロード時最適化

**状態**：未着手

**フェーズ**：M6 管理（M7横断検証前）

**推奨実装順**：T37完了後、T43/T44/T45の最終検証前

**担当**：LUNA-B

**一覧へ戻る**：[implementation-tickets.md](../docs/implementation-tickets.md)

## 目的

商品画像の入力許容範囲を保ちながら、アップロード時に自動でリサイズ・圧縮し、保存される各画像を1MiB（1,048,576 bytes）以下にする。

## 対応要件ID

| ID | 要件・根拠 |
| --- | --- |
| CAT-04 | 管理者が商品情報と画像を登録・編集する。 |
| SEC-01 | 画像の検査・保存は既存の管理認可とサーバー側検証を迂回しない。 |
| USR-IMG-01 | 2026-09-27の利用者追加要件を追跡する本チケット内の識別子（要件定義書の既存IDではない）。入力上限4,000,000 bytesを維持し、アップロード時に自動リサイズ・圧縮して保存画像を1MiB以下にする。 |

## 対象範囲

- T37の商品画像アップロード処理におけるサーバー側の自動リサイズ・圧縮、変換後の検証、Storageへの保存。
- 管理画面の説明・処理結果表示、およびOpenAPI/Zodや運用文書への反映が必要な場合の整合。
- 既存形式（JPEG、PNG、WebP）、8,000px/辺・2,400万画素以下、非アニメーションの検証、EXIF orientationの適用、画像メタデータの除去を維持する。

## 実装内容

- 入力ファイルは現在の上限4,000,000 bytes以下を受け入れ、既存の形式・内容・寸法・画素数のサーバー検査を通した後、保存前に自動でリサイズ・圧縮する。4,000,001 bytes以上は拒否する。
- 出力を1MiB（1,048,576 bytes）以下にする。辺長・アスペクト比を保ち、拡大しない。必要な場合は段階的に縮小・圧縮して上限内に収める。
- 変換後の実バイト数、画像形式とMIME、寸法を検証してからアップロードする。Storageに置く商品画像オブジェクトは最適化済み出力のみとし、元画像は保存しない。
- 変換しても1MiB以下にできない入力は保存せず、管理画面で原因と選び直し等の次の操作を説明する。部分アップロードや商品メタデータだけが残らないよう既存の保存・クリーンアップ動作と整合させる。
- 既存の管理者認可、CSRF/Origin等のAPI検査、画像検査、Storageポリシー、公開配信、過去注文スナップショットを変えない。

## 対象外

- 商品画像以外のアップロード、公開画像配信経路の置き換え、Storage bucket/RLS設計の変更。
- 受け入れ形式の追加・削除、T37が定める入力上限・寸法・画素数の緩和。
- 一括変換や既存Storage画像のバックフィル、画像の手動編集機能。
- 正本にない画質・最低寸法・新しい出力形式の仕様追加。必要と判明した場合は選択肢と影響を報告し、独断で仕様化しない。

## 受け入れ条件

- 4,000,000 bytes以下で既存の形式・寸法等を満たす入力は、保存前に自動最適化され、保存オブジェクトが1,048,576 bytes以下になる。
- 4,000,001 bytes以上、未対応形式、偽装形式、破損画像、寸法・画素数違反はサーバーで拒否され、Storageに保存されない。
- 変換後に1,048,576 bytesを超える画像もStorageに保存されず、分かりやすい入力エラーが表示される。
- 出力は元画像を拡大せず、縦横比を維持する。必要な向き補正を保ち、既存のメタデータ除去を損なわない。出力のContent-Typeと実形式が一致する。
- 保存・再編集・公開画像配信がT37の管理権限・RLS/Storage条件と整合し、非管理者のアップロードを拒否する。既存画像を置き換える際に失敗すれば元画像を失わない。
- 既存の公開条件、画像代替テキスト、過去注文不変、失敗時の入力保持を満たし、最終UI/セキュリティ/全体E2Eで検証できる。

## 必要なテスト

- Vitest：入力上限の境界（4,000,000 / 4,000,001 bytes）、最適化で1MiB以下になる画像、変換後も上限超過する画像、縦横比・拡大なし・EXIF向き・メタデータ除去、Content-Type整合、破損画像。
- サーバー/API：4,000,000 bytes以下のソースを受け付けても最適化済みバイト列だけをStorageへ渡すこと、超過・変換失敗時の非保存、DB保存失敗時のアップロード後クリーンアップ、権限拒否。
- DB/Storage統合：保存オブジェクトの実サイズが1,048,576 bytes以下であること、参照パス・MIME・読み出し画像の整合、既存RLS/公開配信/差替え失敗時の回復。
- Playwright：4MiB未満かつ1MiBを超える画像を選択し、自動最適化の説明と成功を確認。入力上限超過と1MiBに収まらない画像は理由と次の操作を示し、保存されないことを確認。
- T37関連回帰に加え、T43/T44/T45の検証で縮小後画像の表示品質・アクセシビリティ、アップロード境界のセキュリティ、全体シナリオを確認する。

## 完了条件

- 対象範囲と受け入れ条件を満たし、指定の単体・API・DB/Storage・PlaywrightテストとT37回帰が合格している。
- Storage上の実データが1MiB以下である証拠を残し、テストを弱めずに失敗系も確認している。
- 変更点、設計根拠、テスト結果、未解決事項を報告し、T43/T44/T45がT48の成果を検証する依存を反映済みである。
