# T26 カートUIと概算送料

**状態**：未着手  
**フェーズ**：M4 構成とカート  
**推奨実装順**：26/47（番号順ではなく[実装計画](../docs/implementation-plan.md)第3章の順序）  
**一覧へ戻る**：[implementation-tickets.md](../docs/implementation-tickets.md)

## 目的

S06で現在の内容と送料の不確実性を示す。

## 対応要件ID

| ID | 要件定義書の要件 |
| --- | --- |
| ORD-01 | 会員がカート、注文確認、テスト決済、注文完了、注文履歴を利用できる。 |
| ORD-02 | カート内では「概算」と明示して送料を表示する。配送先と必要な条件が確定した購入手続き中に正式送料と内訳を示し、正式金額の確認前に決済しない。 |
| INV-01 | 在庫切れと注文処理中の在庫不足を再現できるテスト方法を用意する。 |

要件定義書の「詳細化待ち」および古い確認待ち表記は、後続の利用者承認と詳細設計の確定内容を適用する。

## 対象範囲

- S06カート画面と概算送料表示。

## 実装内容

- 明細編集、削除、商品小計、送料「概算」、変更・売切れ・空状態、ログイン導線。概算は確定額として決済へ渡さない。
- 数量変更・削除・空状態・売切れ・価格変更、「概算」ラベルと正式見積への導線を実装する。
- 入出力・DB・権限・画面に変更がある場合は、同じチケット内で対応するOpenAPI、Zod、マイグレーション、RLS、テスト、文書を整合させる。

## 対象外

- 住所確定後の正式額、注文生成、引当。
- 他チケットの機能と、正本にない仕様の独断追加。必要なら変更案を報告する。

## 受け入れ条件

- 利用者に概算と正式金額の違いが分かり、在庫不足から数量変更できる。
- 概算を確定額と誤認させず、在庫不足から数量修正できる。
- 設計との不整合、秘密・個人情報の露出、権限の迂回がない。外部設定が未完了なら接続確認を完了扱いにしない。

## 必要なテスト

- Playwrightで匿名/会員、空・売切れ・価格変更、PC/スマホ。
- 匿名/会員、空・売切れ・価格変更、PC/スマホを試す。
- 該当する境界・異常・権限のケースを実行し、既存の関連回帰テストも通す。実行できない場合は理由を記録する。

## 完了条件

- 対象範囲の成果物と受け入れ条件が揃い、指定テストの結果を記録した。
- チケット外の変更、設計上の疑問、外部作業の未完了を隠さず報告した。
- 変更点、設計根拠、テスト結果、残課題をLUNAの完了報告に記載し、レビュー可能な差分になっている。
