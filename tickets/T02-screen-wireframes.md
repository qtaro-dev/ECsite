# T02 画面ワイヤーと遷移レビュー

**状態**：未着手  
**フェーズ**：M0 契約と土台  
**推奨実装順**：02/47（番号順ではなく[実装計画](../docs/implementation-plan.md)第3章の順序）  
**一覧へ戻る**：[implementation-tickets.md](../docs/implementation-tickets.md)

## 目的

製品UI着手前にS01–S17、A01–A06の構造を固定する。

## 対応要件ID

| ID | 要件定義書の要件 |
| --- | --- |
| CAT-01 | カテゴリ、キーワード、用途から商品を探せる。 |
| CAT-02 | メーカー、規格、価格、性能などで絞り込める。カテゴリごとの項目は後述の一覧を基準とする。 |
| CAT-03 | 商品詳細に仕様、税込価格、販売可能な在庫状況、初心者向けの説明を表示する。 |
| CMP-02 | 一致、不一致、判定に必要な情報不足を区別し、比較した仕様と理由を示す。 |
| CMP-04 | 不一致の理由と、適合する商品を探すための具体的な導線を表示する。 |
| CMP-06 | 不一致の警告は構成確認と注文確認に表示する。繰り返すモーダル確認は行わず、注文は妨げない。 |
| ORD-01 | 会員がカート、注文確認、テスト決済、注文完了、注文履歴を利用できる。 |
| ORD-02 | カート内では「概算」と明示して送料を表示する。配送先と必要な条件が確定した購入手続き中に正式送料と内訳を示し、正式金額の確認前に決済しない。 |
| QLT-01 | 主要操作、異常系、権限、在庫・金額の整合性について受け入れ条件を作る。 |

要件定義書の「詳細化待ち」および古い確認待ち表記は、後続の利用者承認と詳細設計の確定内容を適用する。

## 対象範囲

- docs/wireframes/ のS01–S17・A01–A06と画面遷移図。

## 実装内容

- `docs/wireframes/`にPC・タブレット・スマホの主要画面、ヘッダー、検索、構成、カート、注文、認証、管理、警告・空・エラー状態と遷移を作る。デザインルールを添える。
- 各画面の入力、操作、警告、空、読込、失敗、復帰先を描き、0–767/768–1199/1200px以上の3形態を対応付ける。
- 入出力・DB・権限・画面に変更がある場合は、同じチケット内で対応するOpenAPI、Zod、マイグレーション、RLS、テスト、文書を整合させる。

## 対象外

- 画面の製品実装、未設計の新画面の追加。
- 他チケットの機能と、正本にない仕様の独断追加。必要なら変更案を報告する。

## 受け入れ条件

- 詳細設計の全画面IDと主要異常状態が追跡でき、0–767/768–1199/1200px以上の変化が分かる。互換性不一致でも購入導線が残る。
- 一覧の全画面IDを漏れなく追跡し、構成不一致でも購入へ進める。
- 設計との不整合、秘密・個人情報の露出、権限の迂回がない。外部設定が未完了なら接続確認を完了扱いにしない。

## 必要なテスト

- 設計画面一覧との対応表、キーボード操作・文言・320pxレイアウトのレビュー。
- ワイヤーから主要導線と異常導線を人がたどれることを確認する。
- 該当する境界・異常・権限のケースを実行し、既存の関連回帰テストも通す。実行できない場合は理由を記録する。

## 完了条件

- 対象範囲の成果物と受け入れ条件が揃い、指定テストの結果を記録した。
- チケット外の変更、設計上の疑問、外部作業の未完了を隠さず報告した。
- 変更点、設計根拠、テスト結果、残課題をLUNAの完了報告に記載し、レビュー可能な差分になっている。
