# T20 Supabase Send Email HookとSMTP送信

**状態**：未着手  
**フェーズ**：M3 認証と会員  
**推奨実装順**：19/47（番号順ではなく[実装計画](../docs/implementation-plan.md)第3章の順序）  
**一覧へ戻る**：[implementation-tickets.md](../docs/implementation-tickets.md)

## 目的

会員確認・再設定・注文通知のメール送信経路を作る。

## 対応要件ID

| ID | 要件定義書の要件 |
| --- | --- |
| ACC-01 | メールアドレスとパスワードで登録・ログインできる。メール確認を必須とする。 |
| ACC-04 | パスワード再設定を提供する。 |
| ACC-08 | メールは実際に送信できる。SMTP接続設定と環境ごとの送信先設定を管理側で変更できる。接続用の秘密情報は一般利用者や管理画面の通常表示に露出させない。 |
| SEC-01 | テスト用の認証省略機能と管理権限を公開環境の一般利用者に開放しない。 |

要件定義書の「詳細化待ち」および古い確認待ち表記は、後続の利用者承認と詳細設計の確定内容を適用する。

## 対象範囲

- POST /api/auth/email-hook とSMTP送信アダプタ。

## 実装内容

- 署名付きAuth Hook、許可テンプレート、SMTPアダプタ、送信失敗・再送、設定の保護参照、環境別送信先制限。秘密の管理UIはT41。
- Hook署名、テンプレート許可リスト、SMTP秘密参照、環境別宛先制限、失敗時再送導線を実装する。
- 入出力・DB・権限・画面に変更がある場合は、同じチケット内で対応するOpenAPI、Zod、マイグレーション、RLS、テスト、文書を整合させる。

## 対象外

- SMTP管理画面、外部有料契約の無承認実行。
- 他チケットの機能と、正本にない仕様の独断追加。必要なら変更案を報告する。

## 受け入れ条件

- 署名不正を拒否し、秘密をログ・画面に出さず、送信障害時は認証を完了扱いにしない。
- Hook失敗で認証完了扱いにせず、秘密・メール本文をログに出さない。
- 設計との不整合、秘密・個人情報の露出、権限の迂回がない。外部設定が未完了なら接続確認を完了扱いにしない。

## 必要なテスト

- Hook署名・テンプレート・SMTP失敗の統合試験、許可されたテスト宛先への実送信確認。
- 偽署名・無許可テンプレート・SMTP障害・許可宛先への実送信を試す。
- 該当する境界・異常・権限のケースを実行し、既存の関連回帰テストも通す。実行できない場合は理由を記録する。
