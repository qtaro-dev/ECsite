# T30 Stripe CheckoutテストSession

**状態**：未着手  
**フェーズ**：M5 金額と購入  
**推奨実装順**：29/47（番号順ではなく[実装計画](../docs/implementation-plan.md)第3章の順序）  
**一覧へ戻る**：[implementation-tickets.md](../docs/implementation-tickets.md)

## 目的

実課金なしで決済成功・失敗を体験させる。

## 対応要件ID

| ID | 要件定義書の要件 |
| --- | --- |
| ORD-01 | 会員がカート、注文確認、テスト決済、注文完了、注文履歴を利用できる。 |
| ORD-07 | 決済成功・失敗を再現し、失敗時に原因と次に取れる操作を示す。 |
| ORD-08 | 決済方式、注文・在庫の状態遷移、送料の内訳と税額の計算規則を定める。 |
| INV-02 | 決済中だけ在庫を一時引当する。決済失敗または引当期限切れ時は販売可能在庫に戻す。利用者が申し込む取り置き機能とは別の内部処理として扱う。 |
| SEC-01 | テスト用の認証省略機能と管理権限を公開環境の一般利用者に開放しない。 |

要件定義書の「詳細化待ち」および古い確認待ち表記は、後続の利用者承認と詳細設計の確定内容を適用する。

## 対象範囲

- POST /api/checkout/start とStripe CheckoutテストSession。

## 実装内容

- `POST /api/checkout/start`、Stripe CheckoutテストSession、JPY額・注文IDメタデータ・期限・Idempotency-Key、Session保存、作成失敗時の引当解放。カード情報はサイトで受け取らない。
- JPY確定額・注文ID・試行ID・30分期限・冪等キーを送り、Session保存失敗時の回復経路を作る。
- 入出力・DB・権限・画面に変更がある場合は、同じチケット内で対応するOpenAPI、Zod、マイグレーション、RLS、テスト、文書を整合させる。

## 対象外

- ライブ課金、カード情報のサイト保存、Webhook処理。
- 他チケットの機能と、正本にない仕様の独断追加。必要なら変更案を報告する。

## 受け入れ条件

- 注文額とStripe額が一致し、同じ操作の再送で別注文を作らない。ライブ鍵を拒否する。
- Stripe額と注文額が一致し、再送で別注文を作らず、ライブ鍵を拒否する。
- 設計との不整合、秘密・個人情報の露出、権限の迂回がない。外部設定が未完了なら接続確認を完了扱いにしない。

## 必要なテスト

- Stripeテスト環境、SDK失敗・タイムアウト・DB応答不明の統合試験。
- sk_test接続、SDK失敗、タイムアウト、DB応答不明を試す。
- 該当する境界・異常・権限のケースを実行し、既存の関連回帰テストも通す。実行できない場合は理由を記録する。
