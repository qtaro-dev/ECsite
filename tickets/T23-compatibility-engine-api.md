# T23 互換性判定エンジン/API

**状態**：未着手  
**フェーズ**：M4 構成とカート  
**推奨実装順**：22/47（番号順ではなく[実装計画](../docs/implementation-plan.md)第3章の順序）  
**一覧へ戻る**：[implementation-tickets.md](../docs/implementation-tickets.md)

## 目的

5組の比較を一貫した結果で返す。

## 対応要件ID

| ID | 要件定義書の要件 |
| --- | --- |
| CMP-01 | CPU・マザーボードのSocket、マザーボード・メモリのDDR規格、マザーボード・ケースのフォームファクター、GPU・ケースの搭載可能サイズ、CPUクーラー・CPU Socketを判定する。 |
| CMP-02 | 一致、不一致、判定に必要な情報不足を区別し、比較した仕様と理由を示す。 |
| CMP-03 | 不一致でもカート追加と購入を許可する。購入操作を繰り返し妨げる警告にはしない。 |
| CMP-04 | 不一致の理由と、適合する商品を探すための具体的な導線を表示する。 |
| CMP-05 | 判定不能を互換する状態として扱わない。断定的な説明は、判定できた内容の範囲でのみ表示する。 |

要件定義書の「詳細化待ち」および古い確認待ち表記は、後続の利用者承認と詳細設計の確定内容を適用する。

## 対象範囲

- POST /api/compatibility と純粋判定関数。

## 実装内容

- CPU/MB Socket、MB/メモリDDR、MB/ケース形状、GPU/ケース長、クーラー/CPU Socketの`compatible/incompatible/unknown/not_applicable`、理由・比較値・適合一覧URL。OpenAPI/Zodを同期。
- Socket/DDR/ケース形状/GPU長/クーラーSocketの5判定と比較値・理由・適合商品URLを返す。
- 入出力・DB・権限・画面に変更がある場合は、同じチケット内で対応するOpenAPI、Zod、マイグレーション、RLS、テスト、文書を整合させる。

## 対象外

- 高度な互換性や消費電力評価、購入ブロック。
- 他チケットの機能と、正本にない仕様の独断追加。必要なら変更案を報告する。

## 受け入れ条件

- 仕様欠損を一致としない。不一致でも購入可の情報として返し、非公開商品IDは拒否する。
- 欠損はunknown、未選択はnot_applicable。不一致でも購入可の情報として返す。
- 設計との不整合、秘密・個人情報の露出、権限の迂回がない。外部設定が未完了なら接続確認を完了扱いにしない。

## 必要なテスト

- Vitestで5判定×一致/不一致/欠損、APIの権限・リンク・不正ID。
- 各5判定の一致/不一致/欠損、非公開商品ID、適合リンクを試す。
- 該当する境界・異常・権限のケースを実行し、既存の関連回帰テストも通す。実行できない場合は理由を記録する。

## 完了条件

- 対象範囲の成果物と受け入れ条件が揃い、指定テストの結果を記録した。
- チケット外の変更、設計上の疑問、外部作業の未完了を隠さず報告した。
- 変更点、設計根拠、テスト結果、残課題をLUNAの完了報告に記載し、レビュー可能な差分になっている。
