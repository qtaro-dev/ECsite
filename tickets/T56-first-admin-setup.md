# T56 初回管理者アカウントのサイト内セットアップ

**状態**：未着手
**担当**：LUNA-A
**依存**：T06、T10、T17、T20、T36、T44、T50
**利用者決定**：2026-10-01、公開サイト側で管理者アカウントを作れる簡単な導線を追加する。

## 目的・対応要件ID

サイト所有者が公開ECの管理画面へ入れるようにする。ACC-01、ADM-01、SEC-01、SEC-02、QLT-01。一般訪問者が管理権限を自己取得できないことを最優先とする。

## 参照する設計箇所

- 要件定義書の認証・管理者・個人情報、基本設計書の権限分離。
- 詳細設計書・`docs/detailed-design-review.md` の `admin_memberships`、Auth、管理API、監査ログ。
- `docs/admin-access-operations.md` の手動付与は通常の追加・取消しに残す。利用者の最新指示により、管理者が一人も登録されたことのない環境に限る初回セットアップを例外として追加する。

## 対象範囲・実装内容

1. 公開サイトに初回専用のセットアップ画面と管理者ログイン画面を作る。通常の公開デモ会員登録・ログインは変更しない。管理画面への入口にログイン方法を示す。
2. 初回セットアップには、Vercelのサーバー専用環境変数で設定した十分長い一時コード、メールアドレス、12文字以上のパスワードを要求する。コードとパスワードはGit・ログ・URL・ブラウザ保存値へ出さない。
3. サーバーは同一Origin・入力・コードを検証し、Supabase Authの本人用ユーザー作成、`admin_memberships`への初回付与、監査ログを行う。競合時も初回付与は最大1件とし、失敗時に作成したAuthユーザーを安全に片付ける。メール送信が未設定でも、所有者が一時コードを持つ初回作成は成立させる。
4. 既に管理者付与履歴が1件でもある場合は初回セットアップを閉じる。追加管理者・権限取消しは従来のDB管理手順のみ。管理者ログイン後も画面・API・DBの既存権限検証を維持する。
5. セットアップコードの発行・Vercelへの安全な設定・利用者による入力手順を文書化する。外部サービス本人操作が必要な時はSOLがチャットで通知する。

## 対象外

一般会員の公開登録、Google OAuth、SMTP/SMS構築、複数管理者のセルフ招待、管理画面未実装項目、実課金。

## 受け入れ条件

- 所有者は公開サイトの初回画面で管理者を1人作成し、ログインして `/admin` を開ける。
- 一時コードなし・誤り、匿名デモ会員、一般会員、二人目の初回登録は管理権限を取得できない。
- パスワード・一時コード・サービスロール鍵がレスポンス、ログ、Git、`NEXT_PUBLIC_*`に出ない。
- 付与は監査され、失敗・再試行・並行リクエストで不完全な管理権限を残さない。

## 必要なテスト・完了条件

入力・コード・初回判定・競合・ロールバックのVitest/DB統合、一般会員の403と管理者ログインのPlaywright、typecheck/build/lint、必須CIを実行する。公開Supabaseへの新規migration適用とVercel環境変数設定後、所有者のブラウザで初回セットアップ・ログインを確認する。本人のパスワード入力は本人が行い、確認前に本チケットを完了にしない。
