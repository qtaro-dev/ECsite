# T11 テストデータ定義と投入

**状態**：未着手  
**フェーズ**：M1 データと権限  
**推奨実装順**：11/47（番号順ではなく[実装計画](../docs/implementation-plan.md)第3章の順序）

## 目的

要求された正常・異常系を再現可能にする。

## 対応要件ID

| ID | 要件定義書の要件 |
| --- | --- |
| DEM-01 | 在庫切れ、注文処理中の在庫不足、決済成功・失敗、互換性不一致・判定不能を確認できるデータまたはテスト手段を提供する。 |
| CMP-01 | CPU・マザーボードのSocket、マザーボード・メモリのDDR規格、マザーボード・ケースのフォームファクター、GPU・ケースの搭載可能サイズ、CPUクーラー・CPU Socketを判定する。 |
| CMP-02 | 一致、不一致、判定に必要な情報不足を区別し、比較した仕様と理由を示す。 |
| INV-01 | 在庫切れと注文処理中の在庫不足を再現できるテスト方法を用意する。 |
| ORD-07 | 決済成功・失敗を再現し、失敗時に原因と次に取れる操作を示す。 |
| QLT-01 | 主要操作、異常系、権限、在庫・金額の整合性について受け入れ条件を作る。 |

要件定義書の「詳細化待ち」および古い確認待ち表記は、後続の利用者承認と詳細設計の確定内容を適用する。

## 対象範囲

- supabase/seed.sql と期待結果のケース表。

## 実装内容

- `supabase/seed.sql`等に8カテゴリ、互換・不一致・判定不能、売切れ、残数1、9,999/10,000円、20kg境界、料金表のテスト版を定義。実在製品を参考にしても画像・価格の出典を記録し、外部ECから自動取得しない。
- 8カテゴリ、5判定の一致/不一致/欠損、売切れ、残数1、送料無料境界、重量境界、決済成功/失敗を再現する。
- 入出力・DB・権限・画面に変更がある場合は、同じチケット内で対応するOpenAPI、Zod、マイグレーション、RLS、テスト、文書を整合させる。

## 対象外

- 実個人情報、外部EC価格同期、単なる商品件数増加。
- 他チケットの機能と、正本にない仕様の独断追加。必要なら変更案を報告する。

## 受け入れ条件

- ケース表から商品IDと期待結果を追跡でき、実メール・住所・電話番号などの個人情報を含まない。
- 各デモ条件に識別可能な商品と期待結果がある。
- 設計との不整合、秘密・個人情報の露出、権限の迂回がない。外部設定が未完了なら接続確認を完了扱いにしない。

## 必要なテスト

- ローカル再投入の冪等性、データ件数・各ケースの検出試験。
- seed再投入後に件数・期待判定・境界条件が再現する。
- 該当する境界・異常・権限のケースを実行し、既存の関連回帰テストも通す。実行できない場合は理由を記録する。

## 完了条件

- 対象範囲の成果物と受け入れ条件が揃い、指定テストの結果を記録した。
- チケット外の変更、設計上の疑問、外部作業の未完了を隠さず報告した。
- 変更点、設計根拠、テスト結果、残課題をLUNAの完了報告に記載し、レビュー可能な差分になっている。
