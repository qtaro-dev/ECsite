# T33 決済結果・注文履歴画面

**状態**：未着手  
**フェーズ**：M5 金額と購入  
**推奨実装順**：32/47（番号順ではなく[実装計画](../docs/implementation-plan.md)第3章の順序）  
**一覧へ戻る**：[implementation-tickets.md](../docs/implementation-tickets.md)

## 目的

利用者に注文結果と次の操作を示す。

## 対応要件ID

| ID | 要件定義書の要件 |
| --- | --- |
| ACC-07 | 会員は配送先と注文履歴を管理できる。 |
| ORD-01 | 会員がカート、注文確認、テスト決済、注文完了、注文履歴を利用できる。 |
| ORD-06 | 注文に配送先、商品金額、消費税、送料、決済・注文状態を記録する。 |
| ORD-07 | 決済成功・失敗を再現し、失敗時に原因と次に取れる操作を示す。 |
| ORD-10 | 注文後の価格・住所・商品情報の変更が過去の注文表示を変えないよう、注文時点の内容を記録する。 |

要件定義書の「詳細化待ち」および古い確認待ち表記は、後続の利用者承認と詳細設計の確定内容を適用する。

## 対象範囲

- S14/S16/S17の結果・履歴画面。

## 実装内容

- S14/S16/S17、サーバー状態取得、確認中・成功・失敗・期限切れ・要確認、スナップショット表示、再試行導線。カート整理は成功確定後。
- 確認中/成功/失敗/期限/要確認、注文スナップショット、再試行・カート戻りの導線を表示する。
- 入出力・DB・権限・画面に変更がある場合は、同じチケット内で対応するOpenAPI、Zod、マイグレーション、RLS、テスト、文書を整合させる。

## 対象外

- 決済確定ロジック、他人注文閲覧。
- 他チケットの機能と、正本にない仕様の独断追加。必要なら変更案を報告する。

## 受け入れ条件

- Webhook未着なら確認中、失敗を完了と表示しない。他人の注文IDは404相当。
- 戻りURLだけで成功表示せず、変更前の商品・住所で履歴を表示する。
- 設計との不整合、秘密・個人情報の露出、権限の迂回がない。外部設定が未完了なら接続確認を完了扱いにしない。

## 必要なテスト

- Playwright成功/失敗/保留、RLS他人注文、過去商品・住所変更後の履歴。
- Webhook未着、他人注文404、商品/住所変更後履歴を試す。
- 該当する境界・異常・権限のケースを実行し、既存の関連回帰テストも通す。実行できない場合は理由を記録する。

## 完了条件

- 対象範囲の成果物と受け入れ条件が揃い、指定テストの結果を記録した。
- チケット外の変更、設計上の疑問、外部作業の未完了を隠さず報告した。
- 変更点、設計根拠、テスト結果、残課題をLUNAの完了報告に記載し、レビュー可能な差分になっている。
