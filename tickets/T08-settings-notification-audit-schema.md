# T08 設定・通知・監査スキーマSQL

**状態**：未着手  
**フェーズ**：M1 データと権限  
**推奨実装順**：08/47（番号順ではなく[実装計画](../docs/implementation-plan.md)第3章の順序）  
**一覧へ戻る**：[implementation-tickets.md](../docs/implementation-tickets.md)

## 目的

送料・SMTP・認証補助・監査を分離して保存する。

## 対応要件ID

| ID | 要件定義書の要件 |
| --- | --- |
| ACC-05 | メールアドレスとパスワードによる新規会員登録、およびパスワード再設定時に、6桁のSMSワンタイムパスワード認証を行う。通常ログインとGoogleログインではSMS認証を行わない。 |
| ACC-08 | メールは実際に送信できる。SMTP接続設定と環境ごとの送信先設定を管理側で変更できる。接続用の秘密情報は一般利用者や管理画面の通常表示に露出させない。 |
| ORD-03 | 通常送料は全国一律を基本とし、税込商品代金10,000円以上で無料にする。北海道・沖縄県も対象とする。 |
| ORD-04 | ヤマト運輸の取扱いに合わせ、離島であることだけを理由に追加送料を課さない。20kg以上の商品は重量物とし、通常送料が無料でも重量に応じた追加送料を加算する。 |
| ORD-05 | ヤマト運輸の公式料金情報を参照して送料を定め、根拠となる公式ページへのリンクを表示する。発送元は東京都を初期設定とし、管理設定から変更できるようにする。 |
| SEC-01 | テスト用の認証省略機能と管理権限を公開環境の一般利用者に開放しない。 |

要件定義書の「詳細化待ち」および古い確認待ち表記は、後続の利用者承認と詳細設計の確定内容を適用する。

## 対象範囲

- supabase/migrations/ のOTP・送料・SMTP・通知・監査表。

## 実装内容

- `sms_challenges`、`shipping_settings`、`smtp_settings`、`notification_jobs`、`audit_logs`、保護秘密参照のマイグレーション。送料初期値940円、閾値1万円、重量物20kg、東京都発送。
- 送料940円/1万円/20kg/東京の初期値、料金表版、秘密参照、追記専用監査を定義する。
- 入出力・DB・権限・画面に変更がある場合は、同じチケット内で対応するOpenAPI、Zod、マイグレーション、RLS、テスト、文書を整合させる。

## 対象外

- SMTP送信処理、公開送料計算、管理画面。
- 他チケットの機能と、正本にない仕様の独断追加。必要なら変更案を報告する。

## 受け入れ条件

- 秘密平文・OTP平文を表に保存せず、設定版を注文へ参照でき、監査ログが追記専用。
- OTP・SMTP秘密の平文を通常表に保持せず、設定変更履歴を追える。
- 設計との不整合、秘密・個人情報の露出、権限の迂回がない。外部設定が未完了なら接続確認を完了扱いにしない。

## 必要なテスト

- 制約・一意索引・秘密非露出・ローカル再構築。
- 秘密の列・ログへの漏出、料金表欠損時の制約を確認する。
- 該当する境界・異常・権限のケースを実行し、既存の関連回帰テストも通す。実行できない場合は理由を記録する。

## 完了条件

- 対象範囲の成果物と受け入れ条件が揃い、指定テストの結果を記録した。
- チケット外の変更、設計上の疑問、外部作業の未完了を隠さず報告した。
- 変更点、設計根拠、テスト結果、残課題をLUNAの完了報告に記載し、レビュー可能な差分になっている。
