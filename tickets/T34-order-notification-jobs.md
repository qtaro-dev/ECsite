# T34 注文・認証通知のジョブ

**状態**：未着手  
**フェーズ**：M5 金額と購入  
**推奨実装順**：33/47（番号順ではなく[実装計画](../docs/implementation-plan.md)第3章の順序）  
**一覧へ戻る**：[implementation-tickets.md](../docs/implementation-tickets.md)

## 目的

送信失敗が注文状態を壊さない通知を実現する。

## 対応要件ID

| ID | 要件定義書の要件 |
| --- | --- |
| ACC-08 | メールは実際に送信できる。SMTP接続設定と環境ごとの送信先設定を管理側で変更できる。接続用の秘密情報は一般利用者や管理画面の通常表示に露出させない。 |
| ORD-01 | 会員がカート、注文確認、テスト決済、注文完了、注文履歴を利用できる。 |
| ORD-07 | 決済成功・失敗を再現し、失敗時に原因と次に取れる操作を示す。 |

要件定義書の「詳細化待ち」および古い確認待ち表記は、後続の利用者承認と詳細設計の確定内容を適用する。

## 対象範囲

- paid後の通知ジョブとメールテンプレート。

## 実装内容

- `paid`後の注文完了メール一回投入、再試行・失敗監視、認証メールとのテンプレート区分、宛先制限。個人情報をジョブログへ残さない。
- Webhook成功一回に対して一通知をキューへ入れ、送信再試行・失敗監視・環境別宛先制限を実装する。
- 入出力・DB・権限・画面に変更がある場合は、同じチケット内で対応するOpenAPI、Zod、マイグレーション、RLS、テスト、文書を整合させる。

## 対象外

- 決済状態の巻戻し、SMS注文通知。
- 他チケットの機能と、正本にない仕様の独断追加。必要なら変更案を報告する。

## 受け入れ条件

- 決済Webhook重複でも重複メールを送らず、通知失敗で`paid`を戻さない。
- 重複Webhookで重複送信せず、SMTP障害でもpaidを維持する。
- 設計との不整合、秘密・個人情報の露出、権限の迂回がない。外部設定が未完了なら接続確認を完了扱いにしない。

## 必要なテスト

- ジョブ冪等・再試行、SMTP障害、テンプレートと秘密非露出。
- ジョブ冪等、再試行、宛先制限、秘密非露出を試す。
- 該当する境界・異常・権限のケースを実行し、既存の関連回帰テストも通す。実行できない場合は理由を記録する。

## 完了条件

- 対象範囲の成果物と受け入れ条件が揃い、指定テストの結果を記録した。
- チケット外の変更、設計上の疑問、外部作業の未完了を隠さず報告した。
- 変更点、設計根拠、テスト結果、残課題をLUNAの完了報告に記載し、レビュー可能な差分になっている。
