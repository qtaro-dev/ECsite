# T47 公開・運用・ポートフォリオ説明

**状態**：未着手  
**フェーズ**：M7 品質・CI/CD・公開  
**推奨実装順**：47/47（番号順ではなく[実装計画](../docs/implementation-plan.md)第3章の順序）  
**一覧へ戻る**：[implementation-tickets.md](../docs/implementation-tickets.md)

## 目的

採用担当者が操作できる公開デモを安全に提供する。

## 対応要件ID

| ID | 要件定義書の要件 |
| --- | --- |
| QLT-01 | 主要操作、異常系、権限、在庫・金額の整合性について受け入れ条件を作る。 |
| DEM-01 | 在庫切れ、注文処理中の在庫不足、決済成功・失敗、互換性不一致・判定不能を確認できるデータまたはテスト手段を提供する。 |
| ACC-09 | 公開デモのSMSは模擬送信とし、6桁コードの発行・入力・照合を体験できる。公開デモ利用者の電話番号をSMS送信用に収集せず、実SMSを送らない。 |
| ORD-07 | 決済成功・失敗を再現し、失敗時に原因と次に取れる操作を示す。 |
| SEC-01 | テスト用の認証省略機能と管理権限を公開環境の一般利用者に開放しない。 |

要件定義書の「詳細化待ち」および古い確認待ち表記は、後続の利用者承認と詳細設計の確定内容を適用する。

## 対象範囲

- 公開ポートフォリオと運用文書。

## 実装内容

- 公開前チェック、規約・個人情報案内、ヤマト公式リンク、実課金なし表示、利用ガイド、監視・障害・30日削除・バックアップ手順、AI駆動開発の人間による判断とAIの役割を記録。
- 非販売・非課金・非発送、架空住所推奨、30日削除、公式送料リンク、異常系ガイド、AI駆動開発の人間判断を記録する。
- 入出力・DB・権限・画面に変更がある場合は、同じチケット内で対応するOpenAPI、Zod、マイグレーション、RLS、テスト、文書を整合させる。

## 対象外

- 実販売開始、ライブ決済、実SMS公開運用。
- 他チケットの機能と、正本にない仕様の独断追加。必要なら変更案を報告する。

## 受け入れ条件

- PC/スマホで購入体験と異常系を操作でき、実課金・実SMS・実発送なし、個人情報削除、CI/CDの証拠を確認できる。
- 公開URLで購入体験・異常系・プライバシー案内・CI/CD証拠を確認できる。
- 設計との不整合、秘密・個人情報の露出、権限の迂回がない。外部設定が未完了なら接続確認を完了扱いにしない。

## 必要なテスト

- 公開URLのスモーク、全主要シナリオ、監視通知、削除ジョブ、秘密・環境分離の最終確認。
- 公開スモーク、監視通知、削除ジョブ、秘密/環境分離を確認する。
- 該当する境界・異常・権限のケースを実行し、既存の関連回帰テストも通す。実行できない場合は理由を記録する。

## 完了条件

- 対象範囲の成果物と受け入れ条件が揃い、指定テストの結果を記録した。
- チケット外の変更、設計上の疑問、外部作業の未完了を隠さず報告した。
- 変更点、設計根拠、テスト結果、残課題をLUNAの完了報告に記載し、レビュー可能な差分になっている。
