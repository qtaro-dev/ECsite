# T28 住所選択・正式見積・注文確認

**状態**：未着手  
**フェーズ**：M5 金額と購入  
**推奨実装順**：27/47（番号順ではなく[実装計画](../docs/implementation-plan.md)第3章の順序）  
**一覧へ戻る**：[implementation-tickets.md](../docs/implementation-tickets.md)

## 目的

支払い前に最終金額と互換性を確認させる。

## 対応要件ID

| ID | 要件定義書の要件 |
| --- | --- |
| ORD-01 | 会員がカート、注文確認、テスト決済、注文完了、注文履歴を利用できる。 |
| ORD-02 | カート内では「概算」と明示して送料を表示する。配送先と必要な条件が確定した購入手続き中に正式送料と内訳を示し、正式金額の確認前に決済しない。 |
| ORD-06 | 注文に配送先、商品金額、消費税、送料、決済・注文状態を記録する。 |
| CMP-06 | 不一致の警告は構成確認と注文確認に表示する。繰り返すモーダル確認は行わず、注文は妨げない。 |
| INV-01 | 在庫切れと注文処理中の在庫不足を再現できるテスト方法を用意する。 |

要件定義書の「詳細化待ち」および古い確認待ち表記は、後続の利用者承認と詳細設計の確定内容を適用する。

## 対象範囲

- S12/S13、POST /api/checkout/quote。

## 実装内容

- `POST /api/checkout/quote`、S12/S13、配送先、商品現在価格・在庫、送料内訳、内税額、見積期限、互換性警告、差額再確認。OpenAPI/Zodを同期。
- 住所選択、商品・在庫・価格再確認、正式送料・税・総額、互換性短警告、見積期限を実装する。
- 入出力・DB・権限・画面に変更がある場合は、同じチケット内で対応するOpenAPI、Zod、マイグレーション、RLS、テスト、文書を整合させる。

## 対象外

- 在庫引当、Stripe Session作成。
- 他チケットの機能と、正本にない仕様の独断追加。必要なら変更案を報告する。

## 受け入れ条件

- ブラウザ送信額を採用せず、送料算定不能・在庫不足・価格変更を説明して支払いへ進ませない。不一致だけでは支払いを止めない。
- 差額・在庫不足・送料算定不能では決済に進ませず、不一致だけでは妨げない。
- 設計との不整合、秘密・個人情報の露出、権限の迂回がない。外部設定が未完了なら接続確認を完了扱いにしない。

## 必要なテスト

- Vitest見積、API価格改ざん・409/503、Playwright住所なし・警告・差額。
- 改ざん金額、価格変更、住所なし、送料欠損、警告とリンクを試す。
- 該当する境界・異常・権限のケースを実行し、既存の関連回帰テストも通す。実行できない場合は理由を記録する。
