# T18 Google OAuth

**状態**：未着手  
**フェーズ**：M3 認証と会員  
**推奨実装順**：18/47（番号順ではなく[実装計画](../docs/implementation-plan.md)第3章の順序）  
**一覧へ戻る**：[implementation-tickets.md](../docs/implementation-tickets.md)

## 目的

Googleで登録・ログインできるようにする。

## 対応要件ID

| ID | 要件定義書の要件 |
| --- | --- |
| ACC-02 | Googleアカウントで登録・ログインできる。取得する情報はログインと識別に必要な最小限に限る。 |
| ACC-03 | 配送先などECに必要な追加情報は本サイトで入力する。 |
| ACC-05 | メールアドレスとパスワードによる新規会員登録、およびパスワード再設定時に、6桁のSMSワンタイムパスワード認証を行う。通常ログインとGoogleログインではSMS認証を行わない。 |
| SEC-01 | テスト用の認証省略機能と管理権限を公開環境の一般利用者に開放しない。 |

要件定義書の「詳細化待ち」および古い確認待ち表記は、後続の利用者承認と詳細設計の確定内容を適用する。

## 対象範囲

- Google ProviderとOAuth callback、配送先案内。

## 実装内容

- Supabase Auth Google Provider、OAuth callback、最小スコープ、戻り先検査、配送先不足案内。GoogleトークンをアプリDBに保存しない。
- openid email profileだけを要求し、callbackで安全な戻り先を扱い、追加住所はサイトで入力させる。
- 入出力・DB・権限・画面に変更がある場合は、同じチケット内で対応するOpenAPI、Zod、マイグレーション、RLS、テスト、文書を整合させる。

## 対象外

- 通常ログインへのSMS追加、GoogleトークンのアプリDB保存。
- 他チケットの機能と、正本にない仕様の独断追加。必要なら変更案を報告する。

## 受け入れ条件

- GoogleログインにSMSなし、会員識別が安定し、意図しない外部URLへリダイレクトしない。
- Google会員はSMSなしでログインし、他サイトへリダイレクトしない。
- 設計との不整合、秘密・個人情報の露出、権限の迂回がない。外部設定が未完了なら接続確認を完了扱いにしない。

## 必要なテスト

- OAuthフローのテスト環境接続、callback失敗・戻り先拒否、アカウント分離。
- 許可/不許可URL、callback失敗、本人データ分離を試す。
- 該当する境界・異常・権限のケースを実行し、既存の関連回帰テストも通す。実行できない場合は理由を記録する。
