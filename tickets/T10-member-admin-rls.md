# T10 本人・管理者のRLS SQL

**状態**：未着手  
**フェーズ**：M1 データと権限

## 目的

配送先、カート、注文、決済、設定を権限で分離する。

## 対応要件ID

| ID | 要件定義書の要件 |
| --- | --- |
| ACC-07 | 会員は配送先と注文履歴を管理できる。 |
| ORD-06 | 注文に配送先、商品金額、消費税、送料、決済・注文状態を記録する。 |
| ADM-01 | 管理者は注文・決済状態を確認できる。 |
| SEC-01 | テスト用の認証省略機能と管理権限を公開環境の一般利用者に開放しない。 |
| QLT-01 | 主要操作、異常系、権限、在庫・金額の整合性について受け入れ条件を作る。 |

要件定義書の「詳細化待ち」および古い確認待ち表記は、後続の利用者承認と詳細設計の確定内容を適用する。

## 対象範囲

- 本人・管理者・決済関連表のRLS/GRANTと限定DB関数。

## 実装内容

- 本人所有ポリシー、注文に従属する明細・試行、管理者判定関数、非公開スキーマ、限定DB関数の実行権限、既定GRANT剥奪。
- 所有者ID、注文親へのEXISTS、管理者membership、固定search_pathの関数、サービスロール利用境界を設計どおりに設定する。
- 入出力・DB・権限・画面に変更がある場合は、同じチケット内で対応するOpenAPI、Zod、マイグレーション、RLS、テスト、文書を整合させる。

## 対象外

- 公開商品RLS、管理画面UI。
- 他チケットの機能と、正本にない仕様の独断追加。必要なら変更案を報告する。

## 受け入れ条件

- 会員Aから会員Bを読書きできず、自己管理者昇格不可。サービスロール経路は明示されたサーバー処理だけ。
- 会員Aは会員Bの明細・試行をID指定しても読めず、自己昇格不可。
- 設計との不整合、秘密・個人情報の露出、権限の迂回がない。外部設定が未完了なら接続確認を完了扱いにしない。

## 必要なテスト

- RLS許可拒否マトリクス、`auth.uid()=null`、関数search_path、関連明細のID推測試験。
- null auth.uid、関数EXECUTE権限、関連表の越権を試す。
- 該当する境界・異常・権限のケースを実行し、既存の関連回帰テストも通す。実行できない場合は理由を記録する。

## 完了条件

- 対象範囲の成果物と受け入れ条件が揃い、指定テストの結果を記録した。
- チケット外の変更、設計上の疑問、外部作業の未完了を隠さず報告した。
- 変更点、設計根拠、テスト結果、残課題をLUNAの完了報告に記載し、レビュー可能な差分になっている。
