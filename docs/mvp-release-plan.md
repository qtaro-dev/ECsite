# 公開MVP実行計画（2026-09-27）

**2026-09-28の環境・公開範囲の変更**：[単一Hosted DB運用](mvp-hosting-decision-2026-09-28.md)を優先する。Preview/Production別Supabaseという従来案は、今回の限定提示用MVPでは1プロジェクトの順次利用へ変更した。

## 位置づけ

利用者の2026-09-27の指示により、元の49件すべての完了よりも、公開できる購入体験を優先する。閲覧者ごとのデモ認証・架空データ購入のT50/T51を追加し、計51件とする。既存の要件定義・基本設計・詳細設計は機能の設計根拠として残す。この文書は**今回の公開順序と公開時の対象範囲**を定める。個別チケットの元の番号と履歴は維持し、延期した仕様を実装済みと表示しない。元のチケットに公開後の内容が残る場合は、実装報告にその差を明記する。

## MVP完成ライン

公開URLでPCとスマートフォンからサイトを閲覧でき、PreviewとProductionが別のSupabase DB/Auth/Storageおよび別のStripe**テストモード**設定を使う。利用者は公開商品を検索・閲覧し、会員としてカート、配送先、正式見積、注文、Stripe Checkoutテスト決済、結果、注文履歴まで操作できる。署名済みWebhookによって注文と在庫が整合し、決済失敗・期限切れは安全に引当を解放する。戻りURLだけで成功にしない。

公開の購入体験は閲覧者ごとの**Supabase匿名デモ会員（T50）**で行う。共有アカウントは使わず、署名済みの個別セッションと既存RLSを通す。デモ会員はサイトが用意する架空の配送先だけを選び、自由入力の氏名・住所・電話・メールを保存しない（T51）。元の「ゲスト注文なし」は一般ECの本実装方針として残し、この公開MVPのデモ会員に限って利用者が例外を承認した。利用者自身のGoogleアカウントは開発・テスト・管理に限定し、一般閲覧者へ渡さない。一般向けGoogle OAuth（T18）、SMTP確認メール（T20）、SMS（T19）、注文通知メール（T34）、SMTP管理（T41）は公開後とする。公開画面から未提供の登録操作へ誘導せず、アクセス時も明確に案内する。Productionの認証省略は有効にせず、会員間の住所・注文の隔離と30日削除を公開条件とする。

公開時の正常系に加え、在庫不足、決済失敗、Webhook重複・逆順・遅延、期限切れ照合、他人データへのアクセス拒否を検証する。互換性不一致は警告と適合商品への導線を出し、購入は妨げない。サイトには非販売・非課金・非発送、架空住所の推奨、30日削除、送料根拠を明記する。実課金、実SMS、利用者向け取り置きは扱わない。

## 実行・進捗ルール

- LUNA-AはT32、T50、T44、T46、T49を主担当。LUNA-BはT33、T51、T22、T35、T43、T45、T47を主担当。T50とT33は同じファイル・DB・共用試験環境を編集しない場合だけ並行する。T22のSQLとT32/T50のSQLは直列にする。
- チケット着手前に最新main、AGENTS.md、個別票、この計画を確認する。受け入れ条件のうち公開後に回す部分は各PRで明示し、テスト結果を省略・弱化しない。完了していない元チケットを「完了」にしない。
- 実装PRのテスト・レビュー・マージ後に、LUNA-Bが`docs/implementation-status.html`を更新する。MVPの通過状況は別の公開チェック表で示し、51件の実装済み件数と混同しない。
- Sandbox/Preview/Stripeテストモードで安全に戻せる設定・検証は自律的に進める。本人のログイン、契約、費用、実課金、秘密の開示、復旧困難なデータ変更はその時点で確認する。ユーザー素材`Resource/`は変更しない。

## 公開判定

1. 公開URLの閲覧、閲覧者ごとのデモ開始、架空配送先、商品探索、カート、見積、注文、Stripeテスト成功・失敗、結果、履歴がPC/スマートフォンで通る。メール・Google等の未提供登録から注文へ進めない。
2. 支払成功を署名済み実通知で確定し、DBの注文・在庫と表示が一致する。重複通知と期限切れで二重販売しない。
3. 匿名デモAuthユーザーを含む30日削除、2閲覧者間・管理者間の権限、架空データ限定、Productionの認証省略拒否、ライブ決済鍵拒否、秘密非露出を確認する。
4. PreviewとProductionのDB・鍵が分離し、必須CIが成功し、マイグレーションとロールバック方法を記録する。
5. 非販売・非課金・非発送、架空住所の案内、未提供機能、既知の制限をサイトとポートフォリオに明示する。

この5項目の証拠が揃うまで「一般公開完了」としない。公開後チケットが残っても、公開MVPの達成とは区別して表示する。
