### 共有シェル

公開EC・会員画面は同じヘッダーとフッターを使う。管理画面は別のシェルとサイドナビを使う。会員・管理者向けリンクの表示だけで権限を守らず、権限拒否状態も画面として示す。

```text
PC 1200px+    [ロゴ] [検索____________________] [カテゴリ8 / 用途 / 構成] [カート数] [会員]
タブレット   [ロゴ] [検索________________] [カテゴリ / 構成] [カート] [会員]
スマートフォン[ロゴ] [会員] [カート]                 (補助ナビは折りたたみ)
              [検索________________________________________]
              [カテゴリ → → → 横スクロール]
```

フッターには非販売のデモ説明、プライバシー案内、ヤマト運輸公式料金ページ、問い合わせ先を表示する。狭い画面でも本文幅を奪わず、固定フッターや固定操作でフォームエラー・キーボードを隠さない。

## 全画面共通の状態表示

- **読み込み**: 最終レイアウトに近いスケルトン。操作対象がまだ確定していない間は誤操作できる見た目にしない。
- **失敗**: 画面内に「原因」と「次にできる操作」を表示する。入力・検索条件は検証失敗や再読込で可能な限り保持する。秘密、他人の情報、内部例外は表示しない。
- **空**: 単に空白にせず、状態の説明とその画面から可能な次の操作を表示する。公開商品や住所がない場合は設計で定義した探索・登録導線を示す。
- **確認**: 互換性不一致にはモーダルを出さない。破棄や削除など不可逆な操作は対象を示して確認する。入力エラーと決済結果はトーストだけで伝えない。
- **キーボード**: スキップリンク→ページ見出し→主要操作→本文の論理順。絞り込み、タブ、数量、行操作をキーボードで操作でき、結果更新後もフォーカス位置が予測可能。
- **エラー関連付け**: 欄ごとのエラーを入力とプログラム的に関連付け、要約から該当欄へ移動できるようにする。色だけで状態を表さない。

## ロールの表示境界

未ログイン利用者は公開商品、構成確認、匿名カートを使える。配送先・注文確定・履歴は会員本人のみ、管理画面は管理者のみ。拒否されたURLは設計の401/403/404相当画面または安全なログイン誘導へ戻し、他人の存在を漏らさない。SMTP秘密、認証コード、認証情報を画面遷移図や例示値に含めない。
